# BahiSync — project rules for Claude Code

BahiSync turns Indian bank statement PDFs into TallyPrime vouchers. Every row is
verified against the running balance; that check is the product's promise.

## Layout
- `engine/bahisync_engine/` — Python core. `parser.py` is the entry point.
  - `pdf_io.py` open/decrypt PDFs, read words (text layer, else RapidOCR / Tesseract OCR)
  - `layout.py` header-driven table parser (no per-bank code; add header synonyms to `ROLE_KEYWORDS`).
    Rows are stitched by row bands (top-aligned or centred dates), or, when amounts sit on undated
    lines (HSBC), each amount line closes a transaction dated by the latest date above it.
  - `balance.py` running-balance verification, newest-first detection
  - `ledgers.py` ledger suggestions: client rules > default rules > AI > party guess > Suspense
  - `export_tally.py` ledger masters + vouchers XML; `export_excel.py`
  - `ai_suggest.py` optional Claude API suggestions (only when ANTHROPIC_API_KEY is set)
- `engine/service/app.py` — stateless FastAPI service; `engine/index.py` is the Vercel entrypoint.
  The server stores nothing: the browser holds the statement JSON and the client's ledger rules
  (`web/src/lib/recent.ts`) and sends them with every request.
- `engine/tests/` — pytest; `tests/fixtures/make_statements.py` generates synthetic statements
- `web/` — Next.js 15 App Router + Tailwind v4. `/` landing, `/app` upload, `/app/review/[id]` review grid
  (`/app/review/sample-hdfc` is the built-in demo, generated by `engine/tests/fixtures/make_sample.py`).
  - `web/src/lib/applyChoiceClient.ts` applies ledger / group / voucher edits in the browser with no network
    call. It mirrors `apply_user_choice` and `/api/rows/apply`: change both together.
  - `web/src/lib/tallyMasters.ts` reads a client's Tally masters XML in the browser (UTF-16 aware).
  - `web/src/lib/whatsapp.ts` builds the "ask the client" message and parses their reply.
  - `web/src/lib/recent.ts` holds all browser storage: statements (24 h), per-client rules, Tally masters,
    upload history (row hashes only) for the duplicate check, and the client list behind `/app/clients`.
  - `web/src/lib/pdfStore.ts` keeps the uploaded PDF in IndexedDB (24 h) for `components/PdfEvidence.tsx`
    (pdf.js, loaded on demand), which highlights a row from its `evidence` [page, top, bottom].
  - `web/src/components/PrivacyNote.tsx` is the privacy promise shown in the app. Keep it true; update it
    whenever where the PDF goes or who sees it changes.
  The browser calls `/api/*`, which `next.config.ts` rewrites to the engine, except `/api/waitlist`,
  a Next.js route handler that writes to Vercel Blob (private).

## Non-negotiable rules
1. Any change to parsing, amounts, dates, balance or Tally export must keep `cd engine && python -m pytest -q` green, and must add a test for the new case.
2. Money is `Decimal`, never float, everywhere in the engine. Floats only at the Excel boundary.
3. Never commit real bank statements. Real samples go in `engine/samples/` (git-ignored) and must be masked.
4. Never log narrations, amounts or file contents in production logs.
5. The server is stateless: the PDF is parsed in memory and nothing is written anywhere server-side.
   Statements live in the user's browser for 24 hours.
6. Never auto-post to Tally without the review step. Rows that fail the balance check stay flagged.
   A ledger choice never changes other rows silently: similar rows are previewed and confirmed.
   Rows with `review_state == "excluded"` are skipped in the vouchers XML; a new ledger clears `review_state`.
7. Tally group names must be TallyPrime's predefined groups (see `TALLY_GROUPS` in `engine/service/app.py`
   and the same list in `web/src/lib/applyChoiceClient.ts`).
8. After changing the ledger engine, regenerate the demo: `cd engine && python -m tests.fixtures.make_sample`
   (writes `web/src/lib/sample-hdfc.json` and `web/public/sample-hdfc.pdf`).

## Adding support for a new bank layout
1. Put a masked sample in `engine/samples/`, run `python -m bahisync_engine.cli engine/samples/x.pdf`.
2. If the header isn't found, add the bank's column titles to `ROLE_KEYWORDS` in `layout.py`.
3. Add a synthetic layout modelled on it to `tests/fixtures/make_statements.py` (`LAYOUTS`) and a test.
4. Run the full test suite.

## Commands
- Engine tests: `cd engine && pip install -r requirements-dev.txt && python -m pytest -q`
- API: `cd engine && uvicorn service.app:app --reload --port 8000`
- Web: `cd web && npm install && npm run dev` (http://localhost:3000)
- Both via Docker: `docker compose up --build`

## Deployment (Vercel)
- Two Vercel projects from the same GitHub repo: `bahisync-api` (root `engine`, FastAPI preset) and
  `bahisync-web` (root `web`, Next.js). Every push to `main` redeploys both.
- `bahisync-web` env: `BAHISYNC_API_URL` = the API's production URL (read at build time by the rewrite);
  `BLOB_READ_WRITE_TOKEN` comes from the connected Blob store.
- Vercel Functions cap request bodies at 4.5 MB, so uploads are limited to 4 MB.
- Scanned / image-only PDFs (e.g. HSBC e-statements) are read with RapidOCR (pip, models bundled, no
  network calls), up to `MAX_OCR_PAGES` pages; Tesseract is the fallback where installed (Docker).
  The OCR stack keeps the API bundle near 400 MB of Vercel's 500 MB limit: don't add heavy dependencies.
